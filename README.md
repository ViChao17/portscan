# portscan

Go-пакет для конкурентной проверки доступности TCP-портов на одном или
нескольких хостах методом TCP connect.

Пакет предназначен для встраивания в другие приложения: в нём нет CLI,
HTTP-фреймворка, базы данных или брокера сообщений, а также нет глобального
изменяемого состояния. Используется только стандартная библиотека Go.

## Возможности

- TCP connect-сканирование через `net.Dialer.DialContext`;
- IPv4, IPv6 и DNS-имена, включая имена с несколькими A/AAAA-записями;
- дедупликация хостов, IP-адресов и портов;
- список портов, диапазон, объединение наборов и разбор строки вида
  `80,443,1000-2000`;
- ограничение количества одновременных подключений;
- отмена через `context.Context`;
- структурированные результаты с классификацией состояния без сравнения
  текста ошибок;
- один экземпляр сканера безопасно переиспользуется и может работать
  параллельно из нескольких горутин;
- нулевые сторонние зависимости.

## Требования

- Go 1.25.5 (указан в `go.mod`; при необходимости toolchain подтянется
  автоматически).

## Быстрый старт

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ViChao17/portscan"
)

func main() {
	scanner, err := portscan.New(
		portscan.WithConcurrency(100),
		portscan.WithConnectTimeout(500*time.Millisecond),
	)
	if err != nil {
		panic(err)
	}

	results, err := scanner.Scan(
		context.Background(),
		[]string{"192.168.1.10", "192.168.1.11"},
		portscan.Range(1, 1000),
	)
	if err != nil {
		panic(err)
	}

	for result := range results {
		fmt.Printf("%s:%d %s\n", result.Host, result.Port, result.State)
	}
}
```

Если нужен готовый срез, а не поток результатов:

```go
results, err := scanner.ScanAll(ctx, hosts, ports)
```

## Публичный API

### Scanner

```go
func New(opts ...Option) (*Scanner, error)

func WithConcurrency(n int) Option        // по умолчанию 100
func WithConnectTimeout(d time.Duration) Option // по умолчанию 1s
func WithResolver(r Resolver) Option      // по умолчанию net.DefaultResolver

func (s *Scanner) Scan(ctx context.Context, hosts []string, ports PortSet) (<-chan Result, error)
func (s *Scanner) ScanAll(ctx context.Context, hosts []string, ports PortSet) ([]Result, error)
```

- `Scanner` неизменяем после `New`; один экземпляр можно использовать
  повторно и конкурентно.
- `New` возвращает ошибку при некорректных значениях опций
  (`ErrInvalidConcurrency`, `ErrInvalidTimeout`, `ErrInvalidResolver`).
- `Scan` запускает сетевую работу и возвращает канал результатов. Канал
  закрывается после завершения всех проверок. Порядок результатов не
  определён.
- `ScanAll` построен поверх `Scan`, полностью вычитывает канал и возвращает
  срез, отсортированный по хосту, IP-адресу и порту. При отмене контекста он
  возвращает ровно по одному результату на каждую комбинацию
  хост/IP/порт: завершённые проверки сохраняют своё состояние, недостающие
  помечаются `StateCanceled`.

`Resolver` — минимальный интерфейс, совместимый с `*net.Resolver`:

```go
type Resolver interface {
	LookupIPAddr(ctx context.Context, host string) ([]net.IPAddr, error)
}
```

### PortSet

```go
func Ports(ports ...uint16) PortSet
func Range(from, to uint16) PortSet
func ParsePorts(spec string) (PortSet, error)

func (p PortSet) Union(other PortSet) PortSet
func (p PortSet) Ports() []uint16
func (p PortSet) Len() int
func (p PortSet) String() string
```

`PortSet` неизменяем, хранит порты в возрастающем порядке без дублей.
Нулевое значение — пустой набор. Некорректный ввод (`Ports(0)`,
`Range(1000, 1)`) запоминается в наборе и возвращается из `Scan`/`ScanAll`
как `ErrInvalidPort` или `ErrInvalidRange` — это позволяет использовать
конструкторы прямо в аргументах вызова.

Пример:

```go
ports := portscan.Range(1, 1024).
	Union(portscan.Ports(3306, 5432, 6379)).
	Union(portscan.Range(8000, 8100))
fmt.Println(ports) // 1-1024,3306,5432,6379,8000-8100
```

`ParsePorts` разбирает строку `"80,443,1000-2000"`, игнорирует пробелы,
схлопывает дубли и пересечения и проверяет диапазон 1–65535.

### Result

```go
type Result struct {
	Host     string
	IP       net.IP
	Port     uint16
	State    State
	Duration time.Duration
	Err      error
}
```

| Поле | Описание |
| --- | --- |
| `Host` | хост в том виде, в каком его передал пользователь (без пробелов по краям) |
| `IP` | адрес, к которому реально выполнялось подключение; `nil` для невалидного/неразрешённого хоста |
| `Port` | проверяемый TCP-порт |
| `State` | классифицированное состояние |
| `Duration` | время попытки подключения; `0`, если подключения не было |
| `Err` | `nil` для `StateOpen`; иначе исходная ошибка, пригодная для `errors.Is`/`errors.As` |

`IP` — независимая копия: изменение `Result.IP` одним потребителем не влияет
на другие результаты.

### State

| Значение | `String()` | Когда возвращается |
| --- | --- | --- |
| `StateOpen` | `open` | TCP-соединение установлено (и сразу закрыто сканером) |
| `StateClosed` | `closed` | соединение явно отклонено (`ECONNREFUSED` / `WSAECONNREFUSED`) |
| `StateTimeout` | `timeout` | подключение не завершилось за `WithConnectTimeout` |
| `StateUnreachable` | `unreachable` | узел или сеть недоступны (`EHOSTUNREACH`, `ENETUNREACH`, `EHOSTDOWN`, `ENETDOWN` и их аналоги в Windows) |
| `StateCanceled` | `canceled` | проверка отменена через `context.Context` |
| `StateError` | `error` | любая другая ошибка; причина в `Result.Err` |

Классификация выполняется по типу ошибки (`errors.Is`/`errors.As`,
`net.Error.Timeout()`), а не по тексту сообщения.

### Ошибки

| Ошибка | Когда возвращается |
| --- | --- |
| `ErrNoHosts` | пустой список хостов |
| `ErrNoPorts` | пустой набор портов |
| `ErrInvalidPort` | порт 0 или диапазон, содержащий 0 |
| `ErrInvalidRange` | обратный диапазон, например `Range(1000, 1)` |
| `ErrInvalidPortSet` | некорректная строка в `ParsePorts` |
| `ErrInvalidConcurrency` | `WithConcurrency` меньше 1 |
| `ErrInvalidTimeout` | `WithConnectTimeout` не больше нуля |
| `ErrInvalidResolver` | `WithResolver(nil)` |
| `ErrNilContext` | в `Scan`/`ScanAll` передан `nil`-контекст |
| `ErrInvalidHost` | пустой или некорректный IP-литерал; возвращается внутри `Result.Err` |
| `ErrResolveFailed` | не удалось разрешить DNS-имя; возвращается внутри `Result.Err` |

Ошибки конфигурации возвращаются из `Scan`/`ScanAll` до начала сетевой
активности. Ошибка отдельного хоста не прерывает сканирование остальных.

`*ResolveError` содержит исходное имя (`Host`) и нижележащую ошибку (`Err`)
и поддерживает `errors.As`/`errors.Unwrap`.

## Поведение на краевых случаях

### Хосты

| Случай | Поведение |
| --- | --- |
| пустой список | `Scan`/`ScanAll` возвращают `ErrNoHosts` |
| пустая строка или строка из пробелов | по одному результату `StateError` с `ErrInvalidHost` на каждый порт; остальные хосты сканируются |
| IPv4/IPv6-литерал | используется напрямую, без DNS; `[::1]` и `::1` считаются одним хостом |
| некорректный литерал (`999.1.1.1`, `1.2.3.4.5`, `[::gg]`) | `StateError` + `ErrInvalidHost`, DNS-запрос не выполняется |
| DNS-имя | резолвится один раз на уникальное имя до начала проверок |
| несколько A/AAAA-записей | проверяется каждый IP; на каждый IP и порт возвращается отдельный результат |
| неразрешимое имя | по одному результату `StateError` с `*ResolveError` (внутри `ErrResolveFailed`) на каждый порт |
| дубликаты | IP дедуплицируются по канонической форме, DNS-имена — без учёта регистра и завершающей точки; `Result.Host` содержит первое написание |

### Порты

| Случай | Поведение |
| --- | --- |
| пустой список | `ErrNoPorts` |
| порт 0 | `ErrInvalidPort` |
| значение > 65535 | невозможно в API с `uint16`; `ParsePorts` возвращает `ErrInvalidPort` |
| обратный диапазон | `ErrInvalidRange` |
| дубликаты и пересечения | схлопываются, порты сортируются по возрастанию |

### Отмена, конкурентность и медленный потребитель

- Одновременно выполняется не более `WithConcurrency` подключений.
- Каждое подключение ограничено `WithConnectTimeout` и родительским
  контекстом; успешное соединение сразу закрывается.
- После отмены контекста новые проверки не запускаются, активные подключения
  прерываются, начатые проверки возвращают `StateCanceled`, канал результатов
  закрывается.
- Проверки, которые не успели начаться, `Scan` не возвращает. `ScanAll`
  дополняет их результатами `StateCanceled`, поэтому для него количество
  результатов всегда равно
  `число_хостов × число_IP × число_портов`
  (для неразрешённых хостов — `число_хостов × число_портов`).
- Если потребитель читает результаты медленно, сканер естественным образом
  притормаживает (backpressure): память не растёт вместе с числом целей.
  Потребитель, который перестал читать, обязан отменить контекст, иначе
  горутины сканирования будут ждать освобождения канала.
- Пакет не порождает горутин, которые переживают завершение сканирования,
  и всегда закрывает канал результатов ровно один раз.

## Ограничения

- Только TCP connect-сканирование: нет SYN-сканирования, UDP, raw sockets,
  определения ОС, обхода межсетевых экранов и эксплуатации уязвимостей.
- Нет поддержки CIDR-диапазонов адресов.
- Так как используется обычный `connect`, проверки видны в логах целевых
  систем и могут блокироваться межсетевыми экранами.
- DNS-имена разрешаются один раз в начале сканирования; изменения DNS во
  время сканирования не учитываются.
- Порядок результатов в `Scan` не гарантируется; для детерминированного
  порядка используйте `ScanAll`.
- Пакет не выполняет rate limiting сверх ограничения конкурентности.

## Тестирование

```bash
go test -race ./...
go vet ./...
```

Покрытие — около 93% инструкций. Тесты не требуют внешней сети:

- открытые и закрытые порты проверяются на loopback-листенерах;
- отдельно проверяется, что сканер закрывает установленные соединения;
- таймауты, ошибки подключения, отмена в полёте и лимит конкурентности
  проверяются через внедряемый dialer;
- DNS-сценарии (несколько IP, неразрешимое имя, дедупликация) — через
  подменяемый `Resolver`;
- проверены переиспользование сканера, параллельные вызовы, медленный
  потребитель, закрытие канала и заполнение пропусков в `ScanAll`.

## Зависимости

Сторонние зависимости не используются. Всё необходимое — `net`, `context`,
`errors`, `sync`, `slices`, `time` — входит в стандартную библиотеку.
